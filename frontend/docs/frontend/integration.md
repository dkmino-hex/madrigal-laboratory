# Интеграция Frontend с сервисами

Все 36 операций клиента подключены к публичному Gateway. `gateway-mapping.json` содержит реальные method/path/operationId/version; дополнительные операции используются для чтения сессии, ревизий, статуса CSV и изменения доказательств/наблюдений. Источник контракта — корневой `contracts/gateway.openapi.json`, доступный через `/openapi.json`.

`transport.ts` выполняет HTTP-запросы. Адаптеры `shared/api/live/capture.ts`, `workspace.ts` и `analysis.ts` преобразуют сервисные DTO; компоненты получают Zod-модели из `contracts/models.ts`. Raw JSON сервисов не выдаётся за прежний mock envelope. Ошибки, неподходящий контекст и неточные целые значения проверяются явно.

Capture предоставляет записи, версии сборок, сессии, два направления, байты, SourceMap и кадры. Сессия принадлежит конкретной сборке; направления различаются по streamId, даже когда assemblyId совпадает. Кеш сессий ограничен и учитывает Gateway, проект и сборку.

Workspace предоставляет проекты, версии настроек, CSV-журнал, доказательства с полным происхождением, наблюдения и гипотезы, отчёты и обмен ZIP. Доказательства старого API, у которых нет полного контекста потока, отображаются отдельно. Изменение новой гипотезы не удаляет такие данные.

Analysis предоставляет интерпретации и неизменяемые ревизии, preview и запуски по нескольким закреплённым сборкам. `schemaJson` сохраняет точный JSON редактора; `revision` остаётся совместимым входом старого API. `results?view=messages` сохраняет группировку полей и проверок; прежнее плоское представление доступно без `view`. Значения `uint64` читаются через `valueText`.

Jobs сообщают владельца сервиса. CSV и импорт проекта возвращают асинхронное задание; после завершения клиент перечитывает изменённые данные. Готовые артефакты скачиваются по публичному адресу Gateway. Для повторов используются ключи операций, поддерживающих идемпотентность; загрузка Capture дополнительно распознаёт дубликат по SHA256.

`npm run api:generate` обновляет типы, `npm run api:check` проверяет их воспроизводимость и соответствие mapping контракту. `npm run test:e2e:integration` проверяет реальный клиент и production-интерфейс на Docker-сервисах: обе разновидности capture, настройки, CSV, доказательства, гипотезы, ревизии, preview, запуск по двум записям, результаты, отчёт, ZIP и повторное восстановление в ту же БД. Подмена сети и MSW не используются.

Для запуска нужны `MADRIGAL_GATEWAY_URL` и браузер Playwright; на Windows можно выбрать установленный Edge через `MADRIGAL_BROWSER_CHANNEL=msedge`. Gateway должен разрешать origin `http://localhost:5173`. Vite запускается тестом автоматически. Пределы большого нагрузочного профиля из ТЗ требуют отдельного измерения на целевой машине.
