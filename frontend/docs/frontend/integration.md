# Подключение публичного Gateway

Реальные операции frontend пока **не подключены**. `src/shared/api/contracts/gateway-mapping.json` содержит `{}`. В ветке `backend/analysis-workspace` есть `api/openapi.yaml` и Gateway, в `backend/capture` — Workspace/Capture и приёмочный корпус; совместимость frontend с этими версиями ещё нужно согласовать и проверить. Ниже перечислены 35 внутренних операций клиента, а не подтверждённый перечень 35 публичных операций D1. Для каждой реальный OpenAPI path/operationId **не согласован**.

## Точки подключения

- `registry.ts`: operation → method, path с `{parameter}`, operationId, contractVersion, idempotent. Mock использует только изолированный `/__madrigal_mock/v1/<operation>`, который не является предложением публичного API.
- `transport.ts`: публичный origin, path-параметры с encodeURIComponent, GET query, JSON/multipart, requestId, idempotency, timeout/abort, envelope и ошибки. Ни одна страница не обращается к внутреннему сервису.
- `contracts/draft.ts`: временные Zod DTO и предметные модели. `client.ts` валидирует ответ и скрывает envelope; `adaptWindow` дополнительно проверяет контекст, границы и полноту окна. После BASE-02 wire DTO/адаптеры заменяются здесь, включая окончательные CSV, JSON, SourceSpan и manifest. Generated типы сами по себе не заменяют runtime-валидацию.
- `query.ts` / `app/config.ts`: ключи `[mode, projectId, operation, params]`, отмена чтений, ограничения кеша и команд. Исторические входы остаются закреплёнными.

## Общие правила таблицы операций

`P` = projectId; `L` = projectId, captureId, sessionId, streamId, direction, assemblyId, start, length. Идентификаторы непрозрачные строки. `start/length`, размеры, счётчики корпуса и смещения — точные десятичные строки; время ISO с 1–9 дробными знаками и явным UTC offset; поправка — signed nanoseconds string. packetNo в draft — безопасный целый номер кадра от 1; окончательный wire-тип требует BASE-04. Байт — целое 0–255. Диапазон полуоткрытый `[start,start+length)`.

`R` = чтение с AbortSignal, timeout 15 s, не более одного повтора для network/timeout. `W` = UI-команда с ключом на логический запрос, без автоматического retry; подтверждённый результат перечитывается. `U` = File через FormData и upload progress, тот же ключ при повторе того же выбранного файла. `J` = запрос принимает jobId; отмена означает запрос отмены, а не мгновенный CANCELLED. Preview отменяется при замене запроса/уходе со страницы; не создаёт проверку всего корпуса. Окончательная гарантия idempotency каждой операции зависит от Gateway, сейчас её проверяет только MSW.

`Page<T>` = items, nextCursor или null, optional total decimal. Mock отдаёт 20 элементов, Zod ограничивает список 100. Реальные размер страницы и cursor ещё не согласованы. `one`/`array` ниже означают отсутствие paging в текущем draft, а не требование к окончательному API.

Статусы DTO: Project/Capture `READY/IMPORTING/ERROR`; Assembly `READY/BUILDING/ERROR`; Run `QUEUED/RUNNING/COMPLETED/CANCELLED/FAILED/INTERRUPTED`; Job добавляет `CANCEL_REQUESTED`; Artifact `PENDING/READY/FAILED/CANCELLED`. Правило/поле отдельно имеет `PASS/FAIL/INCONCLUSIVE/NOT_APPLICABLE/UNKNOWN` с причиной. Ноль сообщений или применимых правил, partial/unknown не становятся общей зелёной оценкой. Все операции могут вернуть транспортную/доменную ошибку.

## Ошибки, файлы и jobs

Временный success envelope: `{data,requestId}`. Ошибка: HTTP non-2xx, `{error:{code,message,details},requestId}`. HTML/content-type mismatch → UNEXPECTED_CONTENT; malformed JSON → INVALID_JSON; неверные DTO/оси/сегменты → INCOMPATIBLE_RESPONSE. NOT_FOUND/SOURCE_UNAVAILABLE/RUN_UNAVAILABLE не подменяются последней версией. CONTRACT_PENDING возникает до fetch. Network/timeout mutation дают неизвестный результат: пользователь перечитывает состояние и повторяет тот же логический запрос с тем же ключом. Abort не является ошибкой протокола. Диагностика удаляет secret/token/password поля и приватные пути; данные не попадают в telemetry/console.

Upload передаёт File через fetch/FormData. Этот механизм не сообщает точный upload progress, поэтому UI показывает честный неопределённый индикатор; принятие файла и обработка — разные этапы. Настоящий ZIP/PCAP не читается в React и не распаковывается браузером. API download — обычная ссылка браузерного менеджера, origin/credentials/path проверены, полный файл не дублируется в JS. Для маленьких demo downloads MSW fetch/blob применяется отдельно, максимум 2 МиБ, object URL освобождается. Backend должен определить disposition/type/hash/готовность и ограничения файла.

Job owner читается из DTO, не из префикса ID. Отмена перечитывает реальный итог при гонке с COMPLETED. Последние 40 ID хранятся в versioned preferences отдельно по режимам; после reload данные снова запрашиваются у Gateway. Polling ограничен, unknown total использует indeterminate progress. При терминальном статусе инвалидируются связанные resource caches, чтобы IMPORTING из предыдущего чтения не переживал завершение обработки. Авторитетное восстановление после настоящего рестарта сервисов пока не проверено; в mock есть сохраняемое INTERRUPTED и контролируемые timestamps.

## Порядок включения реального API

1. Backend 2/Gateway предоставляет BASE-02 OpenAPI 3.x и публичный origin; Backend 1/2 согласовывают decimal/ns/envelope/idempotency/multipart/pagination/cancel/status semantics. Передать реальные schema CSV/AN-03/ZIP manifest и корпус BASE-01/06.
2. Сохранить контракт в `contracts/gateway.openapi.json` либо задать `MADRIGAL_OPENAPI_FILE`; выполнить `npm run api:generate`. Заполнить mapping только подтверждёнными operationId/path/method/version. Заменить wire DTO/адаптеры и сравнить ответы по смысловым инвариантам.
3. `npm run api:check` проверяет воспроизводимость generated types по OpenAPI, **не** существование/работоспособность mapping и **не** wire-совместимость. Это отдельно проверяется transport/integration тестами с настоящими ответами.
4. Собрать `npm run build`, передать Gateway `dist/`. Public base `/`; static assets `/assets/*`. SPA: `/projects`, `/projects/:projectId`, и дочерние `traffic`, `actions`, `compare`, `interpretations`, `interpretations/:interpretationId`, `hypotheses`, `runs`, `runs/:runId`, `runs/compare`, `artifacts`, `settings`. Fallback на index.html применяется только к SPA; API 4xx/5xx не возвращают HTML.
5. Указать фактические MADRIGAL_* значения реального приёмочного проекта/run/source и запустить `npm run test:e2e:api`. Suite блокирует service workers, не подменяет API через page.route. Сейчас подготовлен read-only smoke проектов/run/source/reload; весь исследовательский/перенос/отказоустойчивый сценарий через API ещё требует реальных данных и расширения API-проверок после согласования контрактов.
6. Пройти R1–R6 и INT-01–05 с владельцами: сверить реальные кадры побайтно, новый run после ревизии, независимый ZIP/hash/повторный анализ, Linux-контрольную нагрузку и документированный AN-16 CLI. Только эти доказательства закрывают реальную часть FE-11.

Preflight требует Gateway URL, файл OpenAPI, mapping основных чтений, реальные P/run/source, HTTP 200 и SPA HTML. При отсутствии любого условия exit 1; тесты не помечаются skipped/green. Проверить все 35 mapping по OpenAPI должен следующий интеграционный этап; preflight сам проверяет минимальные 8 необходимых чтений, а не все операции.

## Воспроизводимые примеры без выдуманных API paths

Mock browser source:

```text
/projects/demo-laboratory/traffic?projectId=demo-laboratory&captureId=capture-baseline&sessionId=session-baseline-1&streamId=stream-baseline-a&assemblyId=assembly-baseline-v1&direction=A_TO_B&start=1000&length=4
```

Запросы клиенту (импорты внутри frontend, не curl к неизвестному endpoint):

```ts
api.bytes(location, { signal }); // абсолютная start/length — строки
api.sources(location, { signal }); // все SourceSpan, включая retransmission
api.createRun(
  { projectId, interpretationId, revisionId, settingsVersion, corpus, filters },
  { idempotencyKey },
);
api.cancelJob(projectId, jobId, { idempotencyKey });
```

CLI отсутствует: его синтаксис и зависимости предоставляет Backend 2 (AN-16). UI не выполняет shell и не выдаёт выдуманный пример за рабочую команду.
## Уточнения после доработки 13 октября

Frontend реализует следующие дополнительные варианты нормализованного контракта. Это описания точки подключения, а не утверждение согласованного wire API; public mapping пока пуст.

- Каталоги captures/interpretations/runs/evidence/assemblies читаются постранично. Историческая assembly из URL разрешается до её реального ID, без подстановки первой версии. Для выбранной модели/run доступны отдельные операции чтения по ID. Ответ с повторяющимся cursor отклоняется как несовместимый.
- Сравнение передаёт отдельные interpretationId/revisionId каждой стороны. В preview возвращаются ID полей именно выбранной модели; повторяющиеся вхождения не дедуплицируются по одному fieldId.
- `saveEvidence` без evidenceId создаёт связь, с evidenceId обновляет её основание/уверенность. Location, actionId, kind и прежние SourceSpan остаются закреплёнными. Если backend разделит create/update endpoints, это отражается в адаптере/registry после согласования. Снимки гипотез/отчётов не переписываются этой операцией.
- `createRun` допускает ответ с job без немедленного Run DTO. UI показывает принятое задание, перечитывает историю при terminal status и не придумывает runId. Если Run DTO уже присутствует, manifest проверяется по запрошенным revisionId/settingsVersion/corpus.
- Размер окна потока 4096 не является пределом raw packet. Текущий Packet DTO принимает полный captured frame до 1 МиБ, сверяет capturedLength с bytes.length и originalLength; UI виртуализирует строки кадра. Для более крупных/постраничных frame responses нужна согласованная wire форма и адаптер.
- SourceSpan больше не ограничены числом 100 в client. UI показывает по 20 исходных участков и читает байты только раскрываемых кадров. Согласовать серверную пагинацию/лимиты sources; текущая временная нормализованная форма — Source[]. У одного TCP-кадра в одной assembly линейное преобразование frameOffset/streamStart должно быть согласованным.
- Job.total=null, '0' и положительное точное количество различаются. Процент вычисляется BigInt; в Number переводится только ограниченная шкала 0–10000.
- Новая API-интерпретация получает JSON backend-ревизии. При отсутствии начальной ревизии frontend не подставляет синтетический demo формат; доступен пустой JSON для редактирования. Полные базовые формы AN-03 уточняются по его фактической схеме.

Регрессии и фактические прогоны: `docs/frontend/completion-2026-10-13/report.md`. Real Gateway/OpenAPI, AN-03, CSV/ZIP, hashes, CLI и общий приёмочный корпус пока не предоставлены. После их передачи обязательны api:generate/api:check/API E2E и межсервисная приёмка.
