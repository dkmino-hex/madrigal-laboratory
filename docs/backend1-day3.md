# Backend 1 — день 3 (14.10.2026)

Основание: «Мадригал_итог_16_октября.docx» и «Мадригал — микросервисы и API.md». Реализованы только Workspace и Capture. Работы следующих плановых дней выполнены досрочно в той же ветке; этот файл фиксирует объём дня 3.

| Задача | Результат |
|---|---|
| WS-04 | Workspace использует `ws_` jobs с постоянными состояниями, этапами, прогрессом и отменой. При старте worker переводит прерванные `RUNNING` в `FAILED` либо `CANCELLED`; автоматического повтора без проверки нет. Повтор импорта проекта с тем же `importId` создаёт новый job только после ошибки. |
| WS-05 | `POST /api/v1/projects/{projectId}/action-log` принимает multipart `file` (CSV), `timezone` и `timeOffsetNs`, сохраняет оригинал по SHA-256 и ставит разбор в очередь. Каждая принятая строка хранит исходный номер, действие, параметры, наблюдаемый результат и исправленное время. Ошибочные строки остаются в `diagnostics_json`; названия действий из PCAP не создаются. |
| WS-06 | `GET /api/v1/projects/{projectId}/actions` поддерживает `from`, `to` (RFC3339 или Unix ns), `type`, `cursor`, `limit` и возвращает `incompleteImports`. В ответе сохраняются параметры и исходная привязка к CSV. |
| WS-07 | `POST/GET/PATCH /api/v1/projects/{projectId}/observations` сохраняют наблюдения и гипотезы, связь с actionId, примеры, контрпримеры и контекст. Capture проверяет принадлежность исходного пакета проекту, границы кадра и, если указан stream, сборку и SourceMap. PATCH меняет формулировку, статус и выбор evidence, но исходные координаты evidence остаются неизменными. |
| WS-08 | `POST /internal/v1/projects/{projectId}/snapshots` читает настройки, CSV-импорты, действия, наблюдения и ссылки на источники в одной транзакции, записывает неизменяемый снимок с SHA-256 метаданных. Незавершённый импорт журнала блокирует снимок. |
| CAP-09 | `GAP`, неизвестное начало и усечённые кадры остаются явными; данные не дополняются нулями. Проверка охватывает соответствующие файлы диагностического корпуса. |
| CAP-10 | Конфликтующие байты сохраняются как альтернативы с SourceMap. Для полного TCP-пакета рассчитывается `checksumStatus`: `VALID`, `INVALID`, `OFFLOADED` (возможная частичная checksum) или `UNKNOWN` для усечения. Список сборок возвращает закреплённые настройки, а карточка пакета — статус и диагностику; сомнительные пакеты не исчезают из индекса. |

Запуск: `go run ./cmd/workspace-service` и `go run ./cmd/capture-service` из `D:\Проекты\madrigal-laboratory`. Workspace — `http://127.0.0.1:8081`, Capture — `http://127.0.0.1:8082`. Для evidence Workspace обращается к Capture по `CAPTURE_INTERNAL_URL` (по умолчанию 8082).

Проверка: `go test ./...`. Интеграционный тест импортирует приложенный `testdata/sample_protocol/action_journal.csv`, проверяет диагностику неверной строки, пагинацию, гипотезу и снимок. Evidence проверен через реальный HTTP-обработчик Capture: точный SourceMap принимается, ссылка на capture другого проекта отвергается. Capture проверяется на всех 12 PCAP/PCAPNG, в том числе gap, truncation, unknown start, overlap и checksum. При `OFFLOADED` речь о признаке частичной checksum, а не о доказанном факте аппаратной разгрузки.
