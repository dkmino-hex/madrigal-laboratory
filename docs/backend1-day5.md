# Backend 1 — день 5 (плановая дата 16.10.2026)

Реализовано 14.10.2026 в пределах Workspace и Capture.

| Задача | Результат |
|---|---|
| CAP-18 | Тест на всех 12 приложенных файлах проверяет packet index, reassembly, gap, unknown start, truncation, conflict, checksum, SourceMap, поиск и перенос. Отдельно проверены усечённый PCAP, синтетический поток из 4096 байтовых сегментов, отмена context и лимит пакетов. Reader прекращает чтение при отмене; лимит — 250 000 пакетов на импорт и 100 МиБ на оригинал. Есть benchmark чтения/сборки корпуса. |
| WS-13 | `GET /api/v1/artifacts/{artifactId}` отдаёт только `READY` ZIP/Markdown с `Content-Type`, `Content-Length`, `Content-Disposition`, `ETag`. Файл сверяется по длине и SHA-256, выдаётся потоково; `BUILDING`/`ERROR` дают 409. |
| WS-14 | Тесты отклоняют испорченный SHA-256, отсутствующий компонент, путь `../` внутри ZIP и недоступный evidence-источник; проверяют повтор `importId`, неготовность проекта при сбое Analysis, продолжение после сбоя и неизменяемость содержимого экспортного снимка при изменении настроек во время сборки ZIP. |

Контрольная команда: `go test ./...` — все пакеты прошли. Замер `go test ./services/capture-service/api -run '^$' -bench BenchmarkReassemblyCorpus -benchtime=3x -benchmem -count=1` на Windows amd64, Intel i7-13620H: 1 741 800 нс/проход, 1 493 765 Б/проход, 12 586 аллокаций/проход. Один проход включает чтение и TCP-сборку всех 12 файлов. Числа зависят от машины и не являются нормативом.

Ограничение при сдаче: совместимость ZIP и отчёта с живым Analysis Backend 2 надо подтвердить после его подключения. Тестовые ответы покрывают согласованный HTTP-контракт, но не заменяют сквозной запуск всей команды.
