| Компонент                | Изменение                                                                                                                                           |

Публичные операции:

- `POST /api/v1/projects/{projectId}/discoveries` — ограниченный исследовательский результат без сохранения наблюдений;
- `POST /api/v1/projects/{projectId}/observations/automatic` — атомарное сохранение с `Idempotency-Key`.

Внутренний маршрут Capture: `GET /internal/v1/projects/{projectId}/captures/{captureId}/research-data`. Он не маршрутизируется наружу через Gateway. Контракты находятся в `contracts/gateway.openapi.json`, инвентаре HTTP и frontend mapping. Новая миграция Workspace: `0008_generated_observations.sql`; прежние миграции не переписаны.

## Как вычисляется предложение

1. Выбраны до восьми READY-записей; закреплена готовая сборка каждой. Получены ограниченные байты и непрерывные физические источники. GAP и конфликт не заполняются.
2. По постоянному префиксу и длине предлагается простой фрейминг; минимум три кадра и не менее 80% прочитанных известных сегментов. При неуспехе показывается явно обозначенный TCP-фрагмент. Группы разделяются по направлению и предполагаемому признаку типа либо длине.
3. Действия заранее индексируются по имени capture и временному окну. Префикс максимального конца окна и двоичный поиск уменьшают повторную работу. Привязка не зависит от искомого значения. Совпадающие противоречивые окна оставляют неизвестное значение.
4. Проверяются signed/unsigned 8/16/32/64 LE/BE, finite float32 LE/BE и делители 1/10/100/1000. Целые и десятичные значения сравниваются точно; большие uint64 не проходят через float64.
5. Для кандидата нужны минимум два совпадения с двумя разными совпавшими значениями и ≥50% подходящих примеров. Декодирования с идентичными значениями дедуплицируются; счётчик совпадений сам по себе не основание считать типы одинаковыми.
6. Сохраняются support/counterexample/inconclusive IDs, статистика, объяснение и до 12+12 физических источников. Изменчивые/постоянные позиции также дают нейтральные предложения наблюдений.
7. Fingerprint включает версию, вход, закреплённые данные и журнал. Полученный текст/схема — предложение; автоматический SUPPORTED не выставляется.

Лимиты перечислены в [руководстве](user-guide.md#15-защитные-пределы-и-частые-вопросы). Кеши и проекции ограничены; matcher action-check строится один раз на run, а не для каждого сообщения. Новые sourceLinks отчёта декодируются и индексируются один раз на отчёт.

## Проверка, отличная от подбора

Созданная схема читает поле из байтов. `action` сравнивает его с журналом нового capture, выбранным независимо по источнику и времени. Run закрепляет снимок журнала. Без однозначного действия получается INCONCLUSIVE, при несовпадении числа — FAIL.

Проверено на отдельном тестовом проекте: три записи использованы для подбора (74 примера), дополнительная четвёртая — только для проверки. `params.threshold_c`, offset 12, int16be ÷100: подбор 9/9, независимый run 3 PASS. Ошибочный offset+1: 3 FAIL; исправленная ревизия: 3 PASS. В дополнительной записи всего 16 сообщений, остальные 13 вне области этой схемы.

Проверены повтор сохранения, транзакционный откат неверного actionId без бесхозных источников, точный JSON, pinned journal, старый run после новой ревизии, Markdown с основаниями и пакетами, ZIP с новыми IDs и восстановленным SourceMap. Production UI проверен в Edge, включая ширину 390 px, матрицу, форму и HEX-подсветку. Новый воспроизводимый E2E — `frontend/e2e/research-api.ts`.

На пользовательском проекте выполнялся отдельный **читающий** поиск, без автоматического сохранения ему наблюдений: 106 примеров, 8 групп, 52 кандидата, около 1,34 с. Среди предложений — `observed.measurements[0].temperature_c`, offset 14, int16be ÷100, 19/19. Это измерение одного небольшого корпуса, не нагрузочный benchmark.

CLI `scripts/apply-interpretation.mjs` проверен отдельно через реальный Gateway: повторное применение исправленной ревизии, 16 сообщений, 3 PASS/0 FAIL, около 0,54 с включая ожидание задания. Результат — run.json и потоковая выгрузка results.ndjson.

## Что дальше не объявляется готовым

Нет универсального определения семантики без журнала, полного request↔response matching, автомата состояний, циклов сложных структур, CRC и доказательства назначения поля одним зелёным статусом. Автоподбор ограничен и не заменяет полный run. Нагрузочный профиль PDF и память на целевой машине не измерены. Подробный статус каждого требования — [сверка с PDF](requirements-audit.md).
