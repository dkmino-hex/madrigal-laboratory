## Архитектура

Принятый вариант сохранён: самостоятельные Go-модули Capture, Workspace, Analysis и Gateway, технический модуль `platform`, корневые CLI/проверки и общая `go.work`. Frontend сохраняет собственные зависимости и сборку.

Analysis разделён на предметные модели и parser в `domain`, сценарии и порты в `application/analysis`, HTTP/SQLite/сетевые адаптеры и `bootstrap`. SQL, HTTP-клиенты и реализация соседних сервисов не импортируются предметными слоями. Snapshot/restore выполняются application-сценарием; остановка Analysis отменяет и дожидается фоновых runs, включая ожидающие семафор. У Gateway bootstrap соединяет входной router с исходящими proxy; искусственные предметные модели ему не добавлялись.

Все 10 файлов исходных миграций Analysis сохранены побайтно. Десятичные координаты, JSON-модели, SQL-схема и существующие маршруты сервисов сохранены. Из Capture HTTP убран импорт filestore: уже существующие ошибки и лимит берутся из его domain.

Compose запускает четыре Go-службы в проекте `madrigal-integration`, с отдельными приватными томами. Он не использует внешнюю сеть или тома старого проекта `madrigal`. Frontend запускается отдельно по своей инструкции.

## Оставшиеся задачи интеграции

Frontend перенесён без изменения его draft-контрактов. `frontend/src/shared/api/contracts/gateway-mapping.json` остаётся пустым: production-сборка не означает, что пользовательские операции уже подключены к Gateway. Нужны согласование публичного OpenAPI, wire DTO и mapping, затем реальные API E2E. Browser E2E в этой проверке не запускались.

Исходный Analysis сохраняет свои interpretation/revision/run/result IDs при импорте. Snapshot/restore в отдельную пустую БД проходит; восстановление копии проекта в ту же Analysis-БД, где исходные записи уже существуют, конфликтует по глобальным ID. Для такого сценария необходимо согласовать ремап внутренних ID и проверить перенос ссылок. Полный проектный ZIP успешно создаётся; его импорт обратно в тот же общий сервер здесь не объявляется работающим.

Существующие ограничения Analysis (например, changeComment и идемпотентность создания интерпретаций) не устранялись при объединении. Их исходное описание сохранено в `README_ANALYSIS_CHANGES.md`. Общая функциональная приёмка UI и переносов остаётся последующим этапом.
