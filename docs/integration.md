# Интеграция и проверка общей рабочей области

Изменения выполнены в `D:\Проекты\madrigal`, ветка `integration/all-services`. `D:\Проекты\madrigal-laboratory` остаётся самостоятельной рабочей копией. Исходные ветки `main`, `backend/capture`, `backend/analysis-workspace` и `frontend/app` сохранены в истории; push на GitHub не выполнялся.

## Единая структура

Capture, Workspace и Analysis имеют собственные Go-модули и слои `domain`, `application`, `adapters`, `bootstrap`, `cmd`, `migrations`. Gateway — технический модуль с HTTP-router, proxy и раздачей SPA. Frontend имеет собственную Node-сборку; HTTP DTO преобразуются в `shared/api/live`, модели интерфейса проверяются Zod. Все Go-модули объединены через `go.work`. Границы зависимостей проверяются тестом архитектуры.

Публичный OpenAPI находится в `contracts/gateway.openapi.json`; mapping и сгенерированные типы проверяются `npm run api:check`. Старый `api/openapi.yaml` сохранён как исторический контракт Analysis; текущим источником служит общий OpenAPI.

## Исправленные проблемы

- Подключены прежние 36 операций Frontend и две новые исследовательские операции к реальным HTTP API. Убраны ожидание mock envelope и пустой mapping.
- Gateway собирает и раздаёт production Frontend, поддерживает reload глубоких ссылок и сохраняет JSON-ошибки неизвестных API. В стандартном Compose наружу опубликован только `127.0.0.1:8080`.
- Список направлений сохраняет оба streamId одной сборки. Диапазоны в API начинаются с 0; контекст сессии проверяется даже при попадании в кеш.
- Workspace сохраняет описание проекта, основание и тип наблюдения, связи с действиями и полное происхождение доказательства. Исходные доказательства старого API остаются доступны.
- CSV поддерживает исходные восемь колонок и формат интерфейса из четырёх. Сохраняются тип действия, точный JSON и наносекунды; поправка времени применяется один раз. Повторы импорта не создают второй журнал, ошибки строк видны после завершения задания.
- Analysis сохраняет точный JSON, комментарий и родительскую ревизию. Создание интерпретаций, ревизий и runs поддерживает повтор запроса с тем же ключом и конфликт другого тела.
- Запуск Analysis закрепляет несколько сборок, реальные SHA256, настройки, диапазоны, сессии и версию движка. Результаты сохраняют сообщения, поля и проверки; старый плоский ответ остаётся доступен.
- Сравнение `uint64` не использует `float64`; точные значения доступны в `valueText`. Проверены соседние значения возле максимума `uint64`.
- Повторное восстановление проекта в ту же БД пересоздаёт собственные IDs Analysis и переносит ссылки Capture/Workspace/Analysis. Восстановленные runs получают доступное терминальное задание.
- Политики checksum `warn`, `strict`, `ignore` учитываются сборкой. В `strict` исключённые байты остаются пропуском; валидная ретрансляция может восстановить их.

## Нагрузка и лишние вызовы

Проверка доказательства выполняется Capture одним HTTP-запросом вместо повторения поиска записей, сборок, кадра и SourceMap в Workspace. Параллелизм frontend-преобразований ограничен шестью запросами, кеш сессий — 128 записями. Состояние задания приходит вместе с запуском, контекст проекта читается один раз на страницу запусков.

Analysis запрашивает не более четырёх диапазонов по 1 МиБ за пакет вместо 256. Просмотр `view=messages` последовательно читает сохранённые части результатов и удерживает одну часть плюс страницу до 100 сообщений. Старый плоский API сохранён для совместимости.

## Понятность рабочего процесса

В проект добавлен раздел «Как работать» с последовательностью исследования, учебным примером поля и объяснением терминов. Обзор проекта показывает первый шаг в зависимости от наличия записей. Журнал явно отличает параметры CSV от полей, найденных в пакетах, показывает выбранное действие и переход к его предполагаемым байтам. Выбранное действие и фильтры сохраняются при возврате из просмотра байтов; обратные ссылки не накапливают вложенные returnTo.

В выборе диапазона видны адреса соединения, направление и объём потока. Полные идентификаторы доступны отдельно. Рабочий редактор показывает поля реальной JSON-схемы и позволяет переименовывать их вместе с зависимыми ссылками правил и lengthFrom. Неизменяемые числовые литералы сохраняются точно. Форма демонстрационного формата показывается только для соответствующей схемы.

Проверены в установленном Edge: справка на экранах 1440 и 390 пикселей, контекст CSV, переход действие → байты → действие и переименование поля реальной схемы. Пользовательские записи при этом не изменялись.
