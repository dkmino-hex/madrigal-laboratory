# Проверка рефакторинга Capture и Workspace

Рефакторинг выполнен поверх рабочей копии с сохранением существовавших изменений. Исходный набор тестов проходил до переноса; после изменений проверены следующие сценарии.

| Проверка | Результат |
|---|---|
| Все модули в рабочей области | `scripts/check.ps1`: тесты, `go vet` и сборка проходят |
| Самостоятельные модули | `GOWORK=off go test ./...` проходит в корне, `platform`, Capture и Workspace |
| Linux | `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 GOWORK=off go build ./...` проходит во всех четырёх модулях; полный набор Go-тестов также проходит внутри `golang:1.26-alpine` из build stage Dockerfile |
| HTTP-контракт | Сохранены 20 регистраций Capture и 19 Workspace, включая jobs, внутренние API и health/readiness |
| HTTP-сценарии | Проверены проекты, настройки, журнал, наблюдения, jobs, отмена, запросы отчёта/экспорта, загрузка проекта и скачивание артефактов; Capture проходит полный сценарий на 12 записях |
| TCP и источники | Проверены поколения соединений, перестановка, ретрансляции, пропуски, конфликты, усечение, checksum, переход sequence number через `2^32`, байты и точные координаты SourceMap |
| Версии и перенос | Старые настройки и assembly остаются доступны; проверены snapshot, ZIP, повторный импорт и сохранность ссылок |
| Ошибки сборки | Отсутствующая запись — 404, неготовая запись — 409, отказ хранилища — 500 |
| Жизненный цикл | Отказ worker останавливает HTTP и остальных workers; отмена дожидается их завершения |
| Реальные процессы | Собранные Windows-бинарники запускаются на временных БД; HTTP-загрузка обрабатывается настоящим worker; после перезапуска обеих служб проект и SourceMap сохраняются |
| CLI | Проверены подготовка записи с обнаружением дубликата и статус миграций |
| SQL | SHA-256 всех 12 существующих миграций совпадает с исходной рабочей копией |
| Compose | `docker compose config --quiet`, сборка образов и запуск с `--wait` проходят; оба контейнера получают статус healthy |
| Docker HTTP | 214 запросов: обработка всех 12 PCAP/PCAPNG настоящими workers, пакеты, сессии, байты, SourceMap, поиск, дубликаты, версии настроек и assembly, закреплённые представления, snapshot ZIP и повторный restore; журнал, наблюдения и проверка evidence между контейнерами |
| Часовые пояса | В runtime-образ добавлен `tzdata`: импорт с Europe/Moscow проходит, местное время `2026-10-15T12:00:00` сохраняется как `2026-10-15T09:00:00Z` |
| Docker CLI и перезапуск | Статус всех 12 миграций и обнаружение дубликата через `capture-prepare` проверены в контейнерах. После restart проект, байты, SourceMap, закреплённое представление и журнал сохраняются. Остановка по SIGTERM завершает оба контейнера с кодом 0 |

Исходный benchmark восстановления на 12 файлах: 12 540 выделений памяти на проход; после оптимизации обычного интервала с одним источником — 11 761. Данные интервалов по-прежнему копируются, чтобы изменения входного буфера не меняли готовый результат.

Анализ функций с инструментированием покрытия использован для поиска пропущенных сценариев и мёртвого кода. Удалён неиспользуемый `testdatabase.Bind`; добавлены проверки ошибок фильтров, ошибок хранилища и владения буфером при переходе sequence number. Неиспользуемая модель восстановленного Capture и вспомогательное нарезание интервалов также удалены: действующий HTTP-сценарий читает диапазоны из приватного хранилища.

После запуска Docker Desktop проверка выполнена на Docker Engine 29.7.2 в отдельном Compose-проекте `madrigal-check`, с временными томами и свободными портами. Локальные процессы на 8081/8082 и существующие тома проекта не изменялись. Проверка выявила отсутствие базы часовых поясов в Alpine: журнал с Europe/Moscow возвращал 400. После добавления `tzdata` весь сценарий повторно прошёл.

Analysis в Go-тестах представлен HTTP-заглушками. В Docker проверен сценарий его недоступности: отчёт и экспорт завершаются явным FAILED, скачивание неготового артефакта возвращает 409, оба сервиса продолжают работать. Реальная совместимость с Analysis и подключение Gateway/Frontend остаются отдельной интеграционной проверкой.
