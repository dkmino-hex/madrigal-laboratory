# Backend 1 — день 4 (плановая дата 15.10.2026)

Реализовано 14.10.2026 в Workspace и Capture по плану и API-документу. Для полного переноса проекта нужны доступные HTTP API Capture и Analysis; Analysis относится к Backend 2.

| Задача | Результат |
|---|---|
| CAP-14 | `GET /api/v1/projects/{projectId}/streams/{streamId}/search?assemblyId=...&mode=HEX|ASCII&pattern=...&limit=...&cursor=...` ищет по готовой сборке, возвращает `[startOffset,endOffset)` и не переносит совпадение через `GAP` или `CONFLICT`. Неверный HEX/режим — 400. |
| CAP-16 | `POST /internal/v1/projects/{projectId}/snapshots` закрепляет готовые captureId/assemblyId. `GET /internal/v1/snapshots/{snapshotId}/archive` выдаёт ZIP с оригиналами, пакетами, сборками, sessions, streams, интервалами, альтернативами, SourceMap и манифестом SHA-256 для каждого файла. |
| CAP-17 | `PUT /internal/v1/projects/{projectId}/imports/{importId}` проверяет структуру ZIP, пути, размеры и хеши, восстанавливает записи с новыми ID и прежними SourceMap-связями. Повтор с тем же `importId` и манифестом возвращает прежние ID; другой манифест даёт 409. Карта версий настроек передаётся заголовком `X-Settings-Version-Map`. |
| WS-09 | `POST /api/v1/projects/{projectId}/exports` создаёт `ws_` job и собирает проектный ZIP из неизменяемого снимка Workspace, CSV-оригиналов и архивов Capture/Analysis. Все компоненты перечислены с SHA-256. Если дочерний сервис недоступен, артефакт не становится `READY`. |
| WS-10 | `POST /api/v1/projects/import` принимает multipart ZIP и опциональный `importId`. До создания проекта проверяются версия, пути, обязательные компоненты, размер и SHA-256 каждого файла. Новый проект получает `IMPORTING`, настройки переносятся в новые версии. |
| WS-11 | Worker повторно проверяет архив, передаёт дочерние ZIP в Capture и Analysis, сохраняет ID дочерних jobs, ждёт их завершения, повторно сверяет evidence с пакетами и SourceMap Capture, переносит журнал/действия/наблюдения с новыми ID и ставит `READY` только после проверки. Время действий в наносекундах сохраняется без округления. Ошибка оставляет `ERROR`; публичное исследовательское чтение Workspace и публичное чтение Capture для неготового проекта возвращают 409. Повтор с тем же `importId` продолжает тот же проект. |
| WS-12 | `POST /api/v1/projects/{projectId}/reports` закрепляет Workspace snapshot и запрашивает завершённый `runId` из Analysis. Job формирует Markdown с данными запуска, наблюдениями, гипотезами, evidence, неизвестными участками и вопросами. Незавершённый запуск не публикуется. |

Ручки 5, 13–18 и 29–30 из API-документа реализованы в зоне Backend 1. Внутренний перенос Analysis вызван по согласованному HTTP-контракту; реальный Analysis ещё не был доступен для сквозного прогона. Интеграционный тест использует тестовый HTTP-сервер Analysis, а Capture ZIP проходит реальный экспорт/восстановление всех 12 приложенных записей с проверкой количества GAP, CONFLICT и SourceMap-связей.

Для WS-11 добавлена внутренняя проверка `POST /internal/v1/projects/{projectId}/evidence/validate`: Capture подтверждает существование пакета, границы кадра и указанную связь SourceMap уже после восстановления своих данных. Workspace вызывает её до публикации `READY`.

Лимиты: Capture импорт ZIP — 250 МиБ сжатых и 750 МиБ распакованных данных, проектный ZIP — 1500 МиБ входного файла и 3 ГиБ суммарного распакованного объёма. Ручки возвращают 400 для повреждённого архива; незавершённый artifact скачивать нельзя.
