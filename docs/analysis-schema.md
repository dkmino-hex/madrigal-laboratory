# Формат интерпретации Analysis 0.3

Интерпретация хранится как точный JSON-текст ревизии. Это формат собственного движка Мадригал; JSON ProtoLab и других программ не импортируется как совместимая схема без преобразования.

## Минимальный пример

```json
{
  "framing": { "fixedLength": 2 },
  "fields": [
    { "name": "value", "type": "int16be", "offset": 0, "scale": 0.01 }
  ],
  "checks": [
    { "id": "bounds", "field": "value", "op": "range", "min": -20, "max": 30 }
  ]
}
```

Для байтов `FF 06` ожидается `valueText: "-2.5"`, PASS правила bounds. Для `13 88` ожидается 50 и FAIL. Эти короткие последовательности иллюстрируют формат; для запуска в приложении нужны реальные байты Capture с SourceMap. Знаковые/масштабные и точные uint64 случаи также проверяются тестами engine.

## Фрейминг

| Поле                           | Смысл                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------- |
| `framing.fixedLength`          | Постоянная длина сообщения в байтах                                             |
| `framing.magic`                | HEX-последовательность начала каждого сообщения                                 |
| `framing.headerLength`         | Размер заголовка для длины из заголовка                                         |
| `framing.lengthOffset`         | Положение числа длины от начала сообщения                                       |
| `framing.lengthType`           | `uint8`, `uint16be/le`, `uint32be/le`                                           |
| `framing.lengthIncludesHeader` | Если true, число длины включает заголовок; иначе движок прибавляет headerLength |

Если длина не задана, выбранный блок рассматривается как сообщение. Предпочитай явный фрейминг для переиспользования. При несовпадении magic нет скрытого поиска следующего подходящего заголовка: остаток выдаётся как неизвестный с диагностикой. Неполная длина/граница диапазона не считается полноценным сообщением.

Полный Analysis поддерживает lengthIncludesHeader; интерактивный автопоиск сейчас предполагает длину полезной нагрузки и не принимает явный режим includesHeader. Это различие возможностей, а не свойство исследуемого протокола.

## Область применимости

На верхнем уровне доступны `direction: "A_TO_B" | "B_TO_A"`, `messageLength` и `match: [{"offset":7,"hex":"20"}]`. Условия match действуют вместе. Несовпавшее сообщение получает NOT_APPLICABLE; недоступные байты условия — INCONCLUSIVE. Поле `scope` хранится, но не является исполняемым языком фильтрации. Для запуска реализован фильтр `{"scope":"all"}`; произвольные условия run не поддерживаются.

## Поля

`fields` — обязательный массив. Имя непустое и уникальное. `offset` отсчитывается от начала сообщения; без него поле следует за предыдущим. `length` задаёт число байтов для строк/байтов; для чисел обычно достаточно типа. `lengthFrom` ссылается на ранее прочитанное беззнаковое целочисленное поле. Не используй масштабируемое поле как lengthFrom: после масштаба его значение уже не исходный uint64.

| Типы                                             | Назначение                                                 |
| ------------------------------------------------ | ---------------------------------------------------------- |
| `uint8`, `u8`                                    | Беззнаковые 8 бит                                          |
| `uint16be/le`, `uint32be/le`, `uint64be/le`      | Беззнаковые числа с явным порядком байтов                  |
| `uint16`, `uint32`, `u16be/le`, `u32be/le`       | Совместимые варианты; для неявного порядка доступен endian |
| `int8`, `int16be/le`, `int32be/le`, `int64be/le` | Знаковые числа, дополнительный код                         |
| `float32be/le`                                   | IEEE float32                                               |
| `string`, `ascii`, `utf8`                        | Текст                                                      |
| `hex`, `bytes`, `base64`                         | Представление сырых байтов                                 |

`endian` для общих типов — `le` или `be`. Явные суффиксы типа удобнее для переносимости. `scale` — ненулевой числовой множитель, например 0.01. Значение поля = декодированное число × scale. В карточке автопоиска это показано как деление на 100.

Для точных больших целых используй `valueText`. JavaScript Number не различает соседние целые около максимума uint64; редактор и адаптер сохраняют точные числовые литералы. Не преобразовывай весь пользовательский JSON через обычные parse/stringify ради косметического изменения.

## Проверки

У каждой проверки уникальный `id`, существующее `field` и `op`:

| op       | Дополнительные поля                     | Поведение                                                      |
| -------- | --------------------------------------- | -------------------------------------------------------------- |
| `eq`     | `value`                                 | Равенство с JSON-значением                                     |
| `range`  | `min`, `max`                            | Числовые границы                                               |
| `length` | `value`                                 | Длина исходных байтов поля                                     |
| `action` | `parameter`, необязательное `tolerance` | Сравнение с числовым значением журнала, допуск неотрицательный |

Пример для `action`:

```json
{
  "id": "threshold_matches_journal",
  "field": "threshold_c",
  "op": "action",
  "parameter": "params.threshold_c"
}
```

Действие выбирается по имени capture и времени пакета, который содержит начало поля. Число не используется для выбора действия. Если однозначного ожидаемого значения нет, возвращается INCONCLUSIVE. При запуске журнал закрепляется в manifest; preview использует журнал, доступный на момент запроса. Проверяется числовое совпадение, не доказанность семантического имени.

`research` в автоматически созданной схеме хранит происхождение подбора, включая SHA-256 обучающей выборки. Это метаданные; они не заставляют движок подставлять ожидаемые ответы и не запрещают пользователю повторный запуск на той же выборке.

## Ограничения

Блок, длина сообщения, смещение и длина поля ограничены 1 МиБ. Обработка корпуса делит потоки на ограниченные диапазоны; сообщение, пересекающее границу такого диапазона, может получить диагностику неполноты. Автоматического переноса состояния парсера между блоками нет. Этот предел требует отдельной проверки на длинных потоках.

Нет циклов по массивам, произвольных вложенных структур, TLV, вычисляемого CRC, произвольных скриптов и модели состояния соединения. Неизвестные JSON-метаданные не становятся исполняемыми правилами. Для сложного протокола схему нужно расширять вместе с движком и тестами.

Применение и команда автоматизации: [руководство, раздел 14](user-guide.md#14-повторное-применение-без-ручного-описания-примеров). Исполняемый пример независимой проверки, ошибочной и исправленной ревизии: `frontend/e2e/research-api.ts`.
